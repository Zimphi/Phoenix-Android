# Android eID / Governikus Panstar verification — 2026-10-21

Test device: Samsung SM-S918B, installed Android commit `c81bb6e`.
TesterArmy opens each actual stored profile, reads its synthetic PIN in memory,
loads the profile into simulation and starts the existing paired WLAN IFD reader.
The existing Phoenix Python PAOS/OpenPACE implementation authenticates against
Governikus' public Panstar test service. No replacement profile or standalone
core emulator is substituted. No PKI, signed DG, PIN or expiry date is rewritten.

## Identity rights: all 21 stored profiles

A successful result requires server-confirmed complete EAC2, followed by HTTP 200
and an identity/result marker on the provider result page. The request requires
DG4 and DG5. Each successful run returned six post-EAC2 card commands.

| Profiles | Result |
| --- | --- |
| PersoSim 01–10 | 10 successful authentications and provider result pages |
| PersoSim UB01–UB05 | 5 successful authentications and provider result pages |
| PersoSim 11 | Provider rejects document validity; its unchanged DG3 expires 2024-06-30 |
| Four editable copies | CVC chain cannot reach the profile EF.CVCA; these use the local test PKI |
| `eid-max` | Android refuses mounting: stored DGs do not match the PersoSim test signatures |

The five protocol rejections were repeated individually after correcting a test
helper prompt matcher. The first helper mistook the prompt text quoted inside a
Python traceback for a second PIN prompt. Those initial timeout/cleanup errors
are excluded as protocol evidence; the targeted rerun supplies the actual errors.
The mount refusal was observed directly in the Android UI, before any Panstar
card operation. Failed cases remain failures; the assertions were not relaxed.

Local evidence: `.e2e/panstar-all-20261021/`,
`.e2e/panstar-recheck-20261021/` and `/private/tmp/phoenix-panstar-*.log`.
Generated device metadata stays outside Git. Logs redact PINs/session URLs and
return only aggregate results, not provider identity data.

## Extended nPA rights

PersoSim 01 and 03 additionally passed the existing `npa-full` request, including
address and standardized municipality verification, with 16 post-EAC2 commands
each and a successful provider result-page fetch. Evidence:
`.e2e/panstar-full-20261021/` (2/2 passed). This does not claim every document type
supports every nPA-specific optional DG.

## Client limitation

The packaged native Phoenix client returned HTTP 400 during PAOS bootstrap,
before any card/PIN operation. The existing Python client successfully establishes
the same service connection and was used for the completed device tests. This
report therefore does not claim native-client Panstar compatibility. No client
trust checks or Android protocol checks were bypassed.

## Repeat

Opt in using `PHOENIX_TEST_PANSTAR_ANDROID=1` and run
`npm run test:e2e:native -- tests/device/panstar_profiles.e2e.ts`.
`PYTHON` must point to Python 3.13 with the existing OpenPACE bindings;
`PHOENIX_PANSTAR_READER` identifies an already paired remote IFD slot.
`PHOENIX_PANSTAR_METADATA` may reference a local JSON list of `{id, serial}`
records to test all stored profiles; it must contain no credentials or keys.
Without metadata the test selects `eid-persosim03`.
Use `PHOENIX_PANSTAR_PROFILE_IDS` for a comma-separated subset and
`PHOENIX_PANSTAR_RIGHTS=npa-full` for the existing extended nPA request.

No new QR login, NFC/REINER SCT repetition, Vercel build or deployment is included.
