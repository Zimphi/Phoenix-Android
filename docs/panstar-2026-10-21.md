# Android eID / Governikus Panstar verification — 2026-10-21

Test device: Samsung SM-S918B, installed Android commit `c81bb6e`.
TesterArmy opens each actual stored profile, reads its synthetic PIN in memory,
loads the profile into simulation and starts the existing paired WLAN IFD reader.
The existing Phoenix Python PAOS/OpenPACE implementation authenticates against
Governikus' public Panstar test service. No replacement profile or standalone
core emulator is substituted. No PKI, signed DG, PIN or expiry date is rewritten.

## Identity rights: all 21 stored profiles

A successful result requires server-confirmed complete EAC2, followed by HTTP 200
and an identity/result marker on the provider result page. The request requires
DG4 and DG5. Each successful run returned six post-EAC2 card commands.

The mount refusal was observed directly in the Android UI, before any Panstar
card operation. Failed cases remain failures; the assertions were not relaxed.

## Native client correction and hardware repeat

The previous native binary returned HTTP 400 before card/PIN access. The cause
was isolated with fresh sessions and identical XML contents: compact SOAP bodies
were rejected; whitespace between elements was accepted. Changing quote style,
namespace declarations or UUID letter case did not explain the failure.
The common native SOAP generator now retains newlines between adjacent elements.
TLS/provider binding and Android/card cores were not weakened or modified.

With the corrected native Rust client (no Python protocol fallback):

- All 15 valid PersoSim profiles (01–10, UB01–UB05) passed full EAC2 over the real
  paired Android IFD reader, six post-EAC2 commands each, with provider result pages.
- PersoSim 01 and 03 passed `npa-full` over IFD: 16 commands and result pages each.
- PersoSim 03 passed `npa-full` over NFC at the physical
  `REINER SCT cyberJack RFID basis`: 16 commands and a provider result page.
- Native verification: 37 Rust tests, five TLS/CLI regression tests, Clippy with
  warnings denied, and the external bootstrap regression passed. The latter and
  the formatting unit test fail against the previous implementation.

Evidence: `.e2e/panstar-native-all-20261021/` (15/15),
`.e2e/panstar-native-full-20261021/` (2/2), and
`.e2e/panstar-native-reiner-20261021/` (1/1).
The local client development asset was replaced with the tested binary; a new
signed desktop release was not produced. The six profile-specific rejection cases
above remain unchanged. Fresh cloud QR login and security reassessment are separate.

## Repeat

Opt in using `PHOENIX_TEST_PANSTAR_ANDROID=1` and run
`npm run test:e2e:native -- tests/device/panstar_profiles.e2e.ts`.
`PYTHON` must point to Python 3.13 with the existing OpenPACE bindings;
`PHOENIX_PANSTAR_READER` identifies an already paired remote IFD slot.
`PHOENIX_PANSTAR_METADATA` may reference a local JSON list of `{id, serial}`
records to test all stored profiles; it must contain no credentials or keys.
Without metadata the test selects `eid-persosim03`.
Set `PHOENIX_EID_CLIENT_BINARY` to the native executable to select the Rust
client; without it the harness uses the explicit Python reference. A PC/SC reader
name in `PHOENIX_PANSTAR_READER` selects NFC instead of IFD.
Use `PHOENIX_PANSTAR_PROFILE_IDS` for a comma-separated subset and
`PHOENIX_PANSTAR_RIGHTS=npa-full` for the existing extended nPA request.

No new QR login, Vercel build or deployment is included.
