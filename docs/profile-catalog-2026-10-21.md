# Profile editor and shared catalogue

Catalogue version 2 supplies eight freshly issued fictional identities from Germany,
France, USA, Japan, Canada, Brazil, South Africa and fictional Utopia. Two have a
nationality different from their issuing state. Ethnicity is not an LDS field.
All products pin the same private catalogue commit and SHA-256; no profile files,
private keys or core binaries are committed to this Apache-licensed app.

The existing licensed shared issuer creates complete format-4 host metadata,
national synthetic CSCA/DS/CVCA/DV/IS chains and signed SODs. Card protocol cores
remain unchanged. The native-only initial data revision is superseded because
the legacy cloud host requires its complete host wrapper. Profiles include their
matching national public CRL; unrelated fallback trust is never used for them.

The 33 former internal test/dev IDs disappear from the supplied selection. Android
first archives matching saved drafts in retired-passport-drafts.json using AtomicFile;
only after a successful archive write does it replace the live list. Independent own
profiles and eID fixtures remain intact. A failed archive/save does not discard the
original file. Catalogue originals stay read-only, own profiles stay editable.

Effective editor values and document schematics use the selected profile. Valid
settings autosave. Selecting a simulation profile mounts it without starting NFC/IFD.
The About page retains actual versions but no longer offers copying version info.

After QR enrollment, the device status authenticates ownership and provides user_id;
the header immediately refreshes. User overview shows that identifier and Abmelden
revokes the device server-side before clearing its local key and cached identity.
Live test results are recorded separately after the service deployment.

## Android profile transfer and document preview

Import and export are at the bottom of the editor's Settings tab. Export uses
Android's document picker and the existing `phoenix-android-draft-v1` JSON format,
including the persisted groups and access settings, limited to 1 MiB. It is not
a backup of generated EF files, PKI keys or runtime card state. Import refuses
an existing ID rather than overwriting a draft.

The passport preview uses the core's MRZ and the DG2 portrait. The Android adapter
compiles the unchanged LDS parser from terminal revision
`81704833cd64182dc54b55a699f83956c537ee08`; source stays in private build inputs.
DG2 opens the portrait viewer even for immutable catalogue profiles. Image dimensions
and decoded byte size are checked before display. eID keeps a schematic silhouette.
The simulation picker shares the large document-type cards with the profile overview.
New profiles are created only after choosing their document type.

DG1 now has individual passport fields. The read-only MRZ preview is generated by
the shared encoder and validated before the editor can apply it. Catalogue
originals remain immutable; editable copies receive their own ID and local test
personalization. ePassport list rows use the passport-cover icon. The transparent
brand assets are reused without modifying their pixels.

Cloud enrollment and PKI live together under Settings → Cloud connection. The QR
capture activity is private and fixed to portrait. The interactive account test
requires a fresh real web QR code and is intentionally separate from unattended
UI tests: `npx e2e run --config e2e.account.config.ts`.

## Device verification, 21 October 2026

The installed debug build passed seven current TesterArmy tests on the connected
Samsung SM-S918B: document editor (three), simulation selection (three), and the
profile/simulation/About/settings UI walkthrough (one). The separate file-transfer
test also exercised a real Android document export and import cancellation.
Thirteen Python repository checks and the on-device native smoke instrumentation
passed; the Android build and lint passed. Reference-based ID/passport screenshots
were inspected for clipping and field placement. Protocol source is unchanged.

Real QR enrollment and revocation were exercised, but the full account-overview
test with the new central account attributes remains pending service deployment

migration are not covered by these Android UI checks.

## Portrait artwork

The male and female anonymous silhouette PNGs are generated artwork, not photographs
copied from the user's document references. The existing transparent Phoenix bird
is reused as a low-opacity watermark. ePassport keeps the actual DG2 portrait when
available; its fallback follows DG1 M/F. eID follows the effective DG11 M/F value or the local Settings → Schattenriss
choice. Names are not used to infer gender; unspecified eID portraits use the
male silhouette.
The optional draft field `portrait_sex` survives saving, copying and JSON export,
but `coreDraft()` excludes it from every native describe/mount/IFD request.

## Mockup rendering and DG editing

Document fields remain dynamic over generated mockup-derived paper artwork. The
passport uses a 720:550 drawing surface with no red border. Native type wrappers
(`GeneralPlace`, `Freetext`, etc.) are removed from display text only; structured
place editing retains its source data. Plain-text birth places open as text.
Signed originals offer “Kopie bearbeiten” from the selected data group. Cancel
creates no profile; accepting creates a separate editable draft and opens that
group, preserving the original catalogue/PersoSim fixture.
